# ADR-0002: Технологический стек — Node.js + TypeScript, pnpm-монорепозиторий

**Статус:** Принято
**Дата:** 2026-07-11

## Контекст

Система — I/O-bound: десятки WebSocket-соединений, парсинг JSON, нормализация, сравнение книг. Вычислительная нагрузка (IV-solver, поверхность волатильности) умеренная. Критичны:

- зрелость WS/HTTP-экосистемы и SDK площадок;
- скорость разработки и единый язык для всех 5 коннекторов (у Polymarket first-class TypeScript SDK — `@polymarket/clob-client` + `ethers`);
- детерминированный replay и тестируемость;
- командная поддерживаемость (один разработчик + AI-агент).

Альтернативы: Rust (быстрее, но медленнее разработка и слабее SDK Polymarket), Go (нет first-class SDK), Python (удобен для research, слабее для live-контура и единого деплоя).

## Решение

| Компонент | Выбор |
|---|---|
| Runtime | **Node.js 22 LTS** |
| Язык | **TypeScript 5**, `strict: true`, ESM (`"type": "module"`) |
| Структура | **pnpm workspaces** — модульный монолит (пакеты + приложения) |
| Тесты | **vitest** |
| Линт/формат | **eslint** + **prettier** |
| Валидация на границах (config, WS/REST payloads) | **zod** |
| Логирование | **pino** (структурированный JSON) |
| WS-клиент | **ws** |
| Деньги/цены/количества | **decimal.js** (или fixed-point `bigint`) — **никакого `number`-float в финансовых расчётах** |
| Время | epoch **миллисекунды UTC** везде; `Date.now()` только на границах |
| Конфиг | env-переменные + zod-схема; секреты только через env |

### Принципы

- Все коннекторы пишутся на одном языке и реализуют единый интерфейс из `packages/core`
- Никаких `any`; внешние данные проходят zod-валидацию на входе в систему
- GC-паузы принимаем: целевая латентность — миллисекунды (ADR-0001)

## Последствия

- **Не** оптимально для микросекундной латентности — осознанный компромисс; при необходимости горячий участок (book builder, matching) можно вынести в Rust-модуль за тем же интерфейсом, не меняя архитектуру
- Decimal-арифметика медленнее float — приемлемо при мс-латентности; запрет float исключает класс ошибок округления в арбитражных сравнениях
- Монорепозиторий упрощает рефакторинг интерфейсов между коннекторами, прайсингом и сигналами
- Все пакеты должны быть пригодны к запуску и в live, и в replay-режиме без изменения кода (см. ADR-0004)
