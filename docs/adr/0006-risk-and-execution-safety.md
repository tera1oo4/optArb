# ADR-0006: Риск-менеджмент и безопасность исполнения сделок

**Статус:** Принято
**Дата:** 2026-07-11

## Контекст

Арбитраж между площадками **неатомарен**: две ноги исполняются на разных биржах/блокчейне, между ними существует leg-риск (одна нога исполнилась, вторая — нет или по худшей цене). Дополнительно: биржи банят за превышение лимитов, Polymarket несёт oracle/settlement-риск (резолюция через UMA, критерии источника цены могут отличаться от индекса Deribit), а ошибка в коде исполнения стоит реальных денег.

## Решение

### Режимы работы

1. **Paper** — режим по умолчанию: сигналы → виртуальные fills по реальным книгам, никаких ордеров наружу
2. **Live** — только при `LIVE_TRADING=true` в env **и** явном подтверждении оператора при старте; отдельные API-ключи с минимальными правами (trade-only, без вывода средств)

### Pre-trade проверки (пакет `risk`, блокирующие)

- Лимит notional на сделку / на инструмент / на площадку / глобально
- Лимиты совокупной экспозиции: delta, vega, gamma (по BTC и ETH отдельно и суммарно)
- Лимит убытка за день/неделю → автоматический переход в paper
- Проверка достаточности маржи/баланса на обеих ногах **до** отправки первой
- Sanity-фильтры сигнала: минимальный edge после комиссий и проскальзывания, max age книги (stale data → запрет), min ликвидность на обеих ногах

### Leg-риск

- Максимальное время между ногами (таймер); при превышении — политика unwind/hedge по заранее заданному правилу (market-ордер на той же или альтернативной площадке)
- Размер ног ограничен долей видимой ликвидности; исполнение через limit-ордера с защитной границей цены, а не «голым» market
- Все переходы состояния двухногой сделки пишутся в аудит-журнал Postgres

### Kill switch

- Глобальный и по-площадочный, в Redis (читается risk-движком на каждый ордер) + CLI/HTTP-триггер
- Автосрабатывание: разрыв sequence книги, потеря heartbeat > N секунд, всплеск reject-ов биржи, превышение day-loss
- При срабатывании: cancel-all открытых ордеров на затронутых площадках, запрет новых входов

### Polymarket-специфика

- Учёт **settlement-риска** отдельным лимитом: суммарный номинал открытых бинарных позиций
- Проверка критериев резолюции рынка (источник цены, время фиксации) до входа — mismatch с индексом хеджирующей биржи = запрет сигнала
- Приватный ключ Polygon — только env, отдельный кошелёк с ограниченным балансом USDC; никогда не логировать
- Соблюдение географических ограничений Polymarket — на стороне оператора/инфраструктуры

### Секреты и аудит

- Все ключи — env-переменные / `.env` (в `.gitignore`); в репозитории только `.env.example`
- Логи (pino) проходят redaction-фильтр по ключам (`secret`, `key`, `passphrase`, `signature`)
- Каждое решение risk-движка (allow/deny + причина) логируется структурированно

## Последствия

- Paper-first — обязательный этап: live включается только после ≥ 4 недель paper-статистики (ADR-0001)
- Любая новая стратегия/детектор не может отправить ордер, минуя `risk` — пакет `execution` принимает только одобренные риск-движком заявки
- Kill switch и лимиты тестируются как код (unit + replay-сценарии «всё пошло не так»), а не «на проде»
- Часть рисков (oracle-спор на UMA, блокировка аккаунта) не устраняется кодом — только лимитами номинала и процедурами
