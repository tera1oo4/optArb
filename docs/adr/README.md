# Architecture Decision Records (ADR)

В этом каталоге фиксируются все значимые архитектурные решения проекта **optArb**.

## Формат

Используется формат Michael Nygard — короткий документ на одно решение:

```
docs/adr/NNNN-kebab-title.md
```

- `NNNN` — порядковый номер с ведущими нулями (0001, 0002, ...)
- Каждый ADR содержит: **Статус**, **Контекст**, **Решение**, **Последствия**
- Проза на русском, технические термины/идентификаторы/код — на английском
- Принятый ADR не редактируется по смыслу; отмена оформляется новым ADR со статусом `Заменяет ADR-XXXX`

## Статусы

| Статус | Значение |
|---|---|
| `Предложено` | Решение обсуждается, ещё не действует |
| `Принято` | Решение действует, код должен ему соответствовать |
| `Заменён` | Отменён другим ADR (указать каким) |
| `Отклонено` | Рассмотрено и не принято (с причиной) |

## Процесс

1. Скопировать шаблон (любой существующий ADR), взять следующий номер
2. Заполнить разделы, статус `Предложено`
3. После ревью — статус `Принято`
4. Добавить строку в индекс ниже

> Для агента kimi есть скилл: `/skill:adr <краткое название решения>` — см. `.kimi-code/skills/adr/SKILL.md`.
