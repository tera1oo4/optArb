# Release review — публикация в GitHub

**Жёсткое правило:** push в `origin` (https://github.com/tera1oo4/optArb.git) выполняется **ТОЛЬКО** после прохождения всех шагов и явного одобрения пользователя. Автоматических commit/push — никогда. Любая git-мутация — с подтверждением на каждое действие.

## Шаг 1. Pre-flight проверки

- [ ] `pnpm test` — зелёный (когда scaffolding готов)
- [ ] `pnpm lint` — без ошибок
- [ ] Секреты: в staged-изменениях нет `.env`, API-ключей, приватных ключей, passphrase, подписей; `.gitignore` покрывает capture-данные, `node_modules`, `.kimi-code/local.toml`
- [ ] В working tree нет мусора и временных файлов

## Шаг 2. Code review (чек-лист optArb)

- [ ] Соответствие ADR: принятые решения не нарушены; новое значимое решение → новый ADR + обновлён индекс (`/skill:adr`)
- [ ] Правила AGENTS.md: decimal/fixed-point вместо float, нет `any`, zod на границах, pino-логи без секретов, ордера только через `risk`
- [ ] Документация синхронизирована: AGENTS.md / скиллы / README, если менялись конвенции
- [ ] **Повышенное внимание**, если затронуты `packages/execution`, `packages/risk`, `packages/venues/*` — код влияет на реальные деньги

## Шаг 3. Diff-анализ (показать пользователю)

1. `git status --short` — что изменилось
2. `git add -A` → `git diff --cached --stat` — объём изменений по файлам
3. Для нетривиальных изменений — `git diff --cached` по ключевым файлам (или структурная сводка изменений)
4. Краткий отчёт: что изменено, зачем, риски, связанные ADR

## Шаг 4. Одобрение

- Покажи отчёт ревью + diff-анализ пользователю
- **Дождись явного подтверждения** («пуш», «ок», «коммить» и т.п.). При замечаниях — исправь и повтори с шага 2

## Шаг 5. Commit + push

- Коммит на **английском**, conventional commits: `feat(venues): add deribit connector`, `docs(adr): add ADR-0007`, `fix(risk): ...`; ссылка на ADR-XXXX в теле при необходимости
- `git push origin <branch>` (по умолчанию `main`)
- Запрещено без отдельного явного разрешения: `push --force`, `--no-verify`, `commit --amend` уже запушенного, `reset --hard`, `rebase`
- После push: отчитайся кратко — sha коммита и ссылка на GitHub
